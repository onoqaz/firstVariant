# 06. Интерфейс и данные


Принципы:

- три постоянные колонки — **что знаю / чем смотрю / что думаю**;
- журнал измерений накапливается автоматически и виден всегда;
- гипотеза подсвечивается: серая = слепая, зелёная = есть подтверждающие улики;
- красным помечены действия, запрещённые контекстом (гарантия, протокол).

## Навигация

Меню трёхуровневое, всё выбирается цифрами — управление одной рукой:

1. **Зона** → список узлов зоны (разъёмы, реле, массы).
2. **Узел** → доступные инструменты для него.
3. **Инструмент** → параметры измерения (пины, режим, условия).

Быстрые команды: `J` журнал, `S` схема, `H` гипотеза, `Q` вопрос владельцу,
`F` фотофиксация, `P` пауза (сохранение).

## Схема цепи

Открывается командой `S`. Пример фрагмента цепи стеклоподъёмника:

```
 АКБ(+) ──[F27 30A]──[K1.30]──┬─[K1.87]── X106.2 ── M ── X106.1 ── G103(масса)
                              └─[K1.85]── кнопка ↑/↓ ── BCM
```

- узлы выбираются курсором/номером; выбранный узел подсвечивает доступные точки измерения;
- найденные на схеме элементы запоминаются как «опознанные» и появляются в зонах;
- на ступени 4+ схема показывает общие точки (splice) — ключ к multi-system.

Ядро — декларативное описание дела. Пример JSON:

```json

  "tier": 3,
  "car": { "make": "Lada Largus", "year": 2013, "arch": "van" },
  "context": { "season": "summer", "weather": "clear",
```

### Узлы цепи

```json
{
  "nodes": {
    "K7": {
      "type": "relay", "zone": "C",
      "state": { "contact": "stuck_closed" },
      "readings": {
        "v_in_rest": 12.6, "v_out_stuck": 12.5,
        "coil_ohm": 68,
        "control_signal": "absent"
      }
    },
    "G103": {
      "type": "ground", "zone": "E",
      "readings": { "drop_under_load_v": 0.05 }
    }
  }
}
```

Правила чтения значений инструментом:

- мультиметр в режиме напряжения возвращает значение при текущем состоянии цепи
  (работает/спит, нагрузка/покой);
- омметр на обесточенной цепи возвращает сопротивление, на живой — ошибку измерения;
- сканер читает таблицу кодов блока с учётом состояния связи (обрыв CAN → «нет ответа»);
- стенд условий применяет модификаторы среды к модели до следующего измерения.

### Реестр причин

Каждая причина из 05 описана один раз как шаблон параметров:

```json
{ "id": "F10", "name": "Залипшее реле",
  "affects": ["any_relay"],
  "signature": { "leak_current": "high", "control_signal": "ignored" },
  "repair": ["replace_relay"], "tier_min": 2 }
```

Генератор дел комбинирует реестры причин, систем, проявлений и обманок по правилам
совместимости (05), проверяет физическую согласованность и выдаёт готовый case_id.

## Сохранения

Автосохранение после каждого действия. Профиль игрока хранит: позицию сюжета,
день календаря, деньги/репутацию, апгрейды, допуски, страницы журнала,
статистику метода (для концовки) и историю дел (для адаптивных тренажёров).

## Технологическая заметка

Ядро не зависит от интерфейса: модель цепи + реестры + правила очков можно запустить
в консоли за первые итерации разработки, а затем подключить любой фронтенд
(TUI, веб, Telegram-бот). Все тексты — во внешних ресурсах: игра полностью русскоязычная,
терминология синхронизирована с курсом.
